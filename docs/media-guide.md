# Media guide

Only use media Swim BASI owns or has permission to publish. Never copy images from the Printful storefront.

## Formats

- Prefer AVIF for the smallest modern image delivery and WebP for broad high-quality support.
- Keep an optimized JPG fallback when source photography or integration requirements need it.
- Use PNG only for transparency or small graphics; avoid it for full-frame photography.
- Campaign video should include MP4 (H.264) and, when practical, WebM versions.
- Every video needs a compressed poster image and meaningful fallback text.

## Dimensions and targets

- Product mockup sources: preferably 2000 × 2000 px with consistent transparent framing.
- Optimized product images: 1200 × 1200 px WebP, generally below 250 KB per view.
- Hero images: 2400 × 1350 px or larger (16:9), ideally below 600 KB.
- Collection/editorial images: at least 1600 px on the longest edge.
- Instagram previews: 1200 × 1200 px.
- Campaign video: 1080p, muted-safe, 6–15 seconds for loops, target below 8 MB; avoid shipping long autoplay video.

## Naming

Use lowercase kebab case: `basi-brink-pink-one-piece-front.webp`, `summer-2026-hero.avif`, and `summer-2026-campaign-loop.webm`. Include product, color, view, and version only when useful.

## Storage

- `public/brand/` — approved brand marks
- `public/images/hero/` — homepage heroes and posters
- `public/images/campaigns/` — campaign/editorial stills
- `public/images/products/` — product views
- `public/images/collections/` — collection covers
- `public/images/instagram/` — curated social previews
- `public/videos/campaigns/` — MP4/WebM campaigns
- `public/icons/` — favicon and UI assets

## Product mockup workflow

`Swim Mockups/` is a local source-import directory. Keep one lowercase, hyphenated folder per
product using `<color>-<silhouette>`, with supported view filenames `front.png`, `back.png`,
`left.png`, and `right.png`. Source PNGs must preserve alpha transparency and should use consistent
canvas dimensions and product framing within a silhouette.

The raw directory is intentionally ignored by Git. Production assets are generated into:

```text
public/images/products/<category>/<product-slug>/<view>.webp
```

Categories use `one-piece`, `string-bikinis`, or `high-waisted-bikinis`. Product directories use the
verified site slug from `src/data/products.ts`. Do not rename catalog products or invent a mapping to
accommodate a source folder.

Run the importer from the repository root:

```sh
npm run images:products
```

The script in `scripts/optimize-product-images.mjs` validates PNG readability and transparency,
preserves the consistent source canvas, resizes without upscaling or distortion, writes alpha WebP
assets, and updates `src/data/product-image-manifest.json`. It fails on missing mapped folders,
duplicate product/folder mappings, duplicate views, corrupt files, unsupported filenames, or missing
transparency. Existing outputs are only rewritten when their generated bytes change.

`scripts/product-image-mapping.mjs` is the human-readable, deterministic folder-to-product mapping.
Add or correct mappings there; never rely on fuzzy matching. Known filename normalization must be an
explicit `sourceViewAliases` entry.

The generated manifest records the source folder, primary and hover assets, gallery order, available
views, dimensions, optimized byte size, alt text, mapping status, and audit totals. It contains only
repository-relative source labels and public web paths—never local absolute paths.

To add a product mockup:

1. Confirm that the product already exists in `src/data/products.ts` with its approved name and slug.
2. Add the transparent source PNGs under `Swim Mockups/<color>-<silhouette>/`.
3. Add one explicit mapping in `scripts/product-image-mapping.mjs`.
4. Run `npm run images:products`, review unmatched-folder output, and inspect every generated view.
5. Run format, lint, check, build, and verification before committing optimized assets and manifest.

If a folder cannot be matched safely, leave it in the local raw directory and do not map it to
another product. If a product lacks a folder, keep its intentional color-preview fallback until an
approved match is available.

## Replacing placeholders

For product mockups, use the workflow above rather than editing page components or manifest paths by
hand. For campaign and editorial media, add the optimized asset and update its central reference.
Supply concise alt text describing the product, color, and view. For video, pass `video`, `poster`, and
accessible fallback text to `MediaFrame`. Test at mobile and desktop widths and rerun the production
build.
